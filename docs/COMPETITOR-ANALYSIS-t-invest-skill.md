# Конкурентный анализ: `nyxandro/t-invest-skill` vs TInvestSkills

> Дата: 2026-07-04
> Источник: https://github.com/nyxandro/t-invest-skill (v1.0.0, релиз 2026-07-03)
> Цель: понять, что перенять, что улучшить, что отбросить, и сформировать план развития.

---

## 0. TL;DR — главные выводы

**Кратко о конкуренте.** `t-invest-skill` — это **один самодостаточный скилл** на
Node.js (TypeScript → один бандл `tinvest.cjs`, ~8.3 тыс. строк, без внешних
npm-зависимостей в рантайме) для доступа к **брокерскому счёту Т-Инвестиций**.
Ставится в один `curl | bash`, работает в любом агенте, читающем `SKILL.md`. Это
**продукт**, доведённый до «зрелого v1.0»: продуманная модель безопасности,
единый CLI, XIRR-доходность, YTM облигаций, скринеры, торговля с гейтами, эвалы.

**Кратко о нас.** TInvestSkills — **рабочее пространство из 4 репозиториев**
(`t-invest-agent` + `t-invest-core` + `moex-core` + `news-core`, плюс
`memory-core`) на PHP/Symfony. У нас **больше охват источников данных** (второй
провайдер — MOEX ISS, агрегатор новостей, соц. настроения, дашборд, рецепты,
мониторинг), но **тоньше глубина аналитики** и **слабее упаковка/безопасность для
конечного пользователя**. По сути — у нас «шире, но мелко», у них «уже, но вглубь
и в продакшен».

**Главное, что у них есть, а у нас нет:**
1. **Безопасная модель работы с деньгами** (3 режима/токена, гейт реальных сделок
   в env, `--confirm`, идемпотентность `--order-id`, аудит-журнал, гард
   ликвидности).
2. **Готовый торговый CLI** (`order preview/buy/sell/cancel/replace`,
   `stop-order`) — у нас код `OrdersService` есть, но CLI-команд нет.
3. **Финансовая математика «на своей стороне»**: XIRR доходности счёта, YTM и
   дюрация облигаций (XIRR-бисекция, ACT/365), структура портфеля (allocation),
   скринеры по всему каталогу — у нас этого нет как готовых команд.
4. **Поставка как самодостаточный `.skill` + `install.sh`** — один файл, ноль
   зависимостей, авто-обновление без потери токенов.
5. **Дисциплина режимов в самом `SKILL.md`** (персистентная сессия, выбор режима
   в начале диалога, русские коды ошибок `APP_TINVEST_...`, `references/` с
   ловушками полей JSON, evals).

**Главное, что есть у нас, а у них нет:**
1. **MOEX ISS как второй/резервный источник** + торговый календарь MOEX.
2. **Агрегатор новостей из 6 RSS** (Интерфакс, ТАСС, РИА, PRIME, РБК, Коммерсант)
   с кэшем и поиском — у них `news` идёт из самого T-Invest API (один источник).
3. **Анализ соц. настроений** (SmartLab, MFD, Banki.ru) — у них отсутствует.
4. **«Продуктовый» слой агента**: `recipe` (торговые журналы), `monitor`
   (алерты/расписания), `memory` (профиль инвестора), **HTML-дашборд на ECharts**.
5. **Мульти-провайдерная архитектура** + документация по мульти-агентной
   оркестрации, промпт-шаблоны (dashboard, morning-check, weekly-report).
6. **Чистый enterprise-style PHP-стек**: DTO, мапперы, сервис-компоненты,
   phpstan/psalm/phpcs, тесты — зрелая архитектура под долгое развитие.

**Вывод одной строкой:** мы — «более широкий аналитический комбайн», они —
«доведённый до ума продукт для доступа к счёту с торговлей». Самые ценные вещи к
перенятию — **модель безопасности, торговый CLI, финансовая математика (XIRR,
YTM, allocation, screeners), упаковка `.skill` + evals**. Самое ценное, что надо
сохранить и развивать у себя — **MOEX, новости, соц. настроения, рецепты,
мониторинг, дашборд**.

## 2. Оценки фич (шкала 1–10)

Шкалы:
- **К** — качество реализации (1 = плохо/нет, 10 = эталон).
- **Н** — нужность (1 = можно обойтись, 10 = критически необходимо).
- **ГП** — «готовность продукта»: насколько фича доведена до пользователя (документация, ergonomics, безопасность, поставка). 1 = сыро, 10 = «plug-and-play».

> Знак «—» = фича отсутствует у стороны. Оценка качества для отсутствующего = 0.

## 3. Что взять у них (Roadmap по приоритетам)

Приоритет = f(Н − разрыв). Отсортировано по impact/effort.

### 🔴 P0 — критично, перенять как можно скорее

1. **Модель безопасности денег (режимы + гейты + аудит).**
   - 3 токена: `T_INVEST_TOKEN_SANDBOX / READONLY / FULL`.
   - Гейт реальных сделок: env-флаг `T_INVEST_ALLOW_TRADING`, обязательный
     `--confirm` на каждую заявку, опасный `STONKS_MODE`.
   - Идемпотентность `--order-id` (UUID), гард ликвидности (проверка стакана/
     спреда перед market-ордером), аудит-журнал `trades.log`.
   - Персистентная «сессия режима» (`session start/status/end`), выбор режима в
     начале диалога.
   - **Где делать:** `t-invest-core` (новый `Trading` слой + команды). Это
     превратит наш «спящий» `OrdersService` в боевой безопасный модуль.

2. **Торговый CLI** (поверх нашего `OrdersService`):
   - `order preview/buy/sell/list/status/cancel/replace`,
   - `stop-order set/list/cancel`, `sandbox init`.
   - `-q` = ЛОТЫ (явный пересчёт «штук» → лотов), preview суммы и комиссии.

3. **Финансовая математика «на своей стороне»** (T-Invest API этого не отдаёт):
   - `performance` — **XIRR доходности счёта** по денежным потокам (с корректным
     выбором корня при чередовании вводов/выводов), вложено/выведено, чистый
     результат, див/купоны/комиссии/налоги.
   - `bond` — **YTM к погашению/оферте + дюрация Маколея** (XIRR-бисекция,
     ACT/365), честный `null` + причина для флоатеров/амортизации/бессрочных.
   - `allocation` — структура (классы/сектора/валюты/страны/концентрация).
   - `screen bonds` / `screen shares` — скринеры по всему каталогу с локальным
     кэшем. **Где:** `t-invest-core` (новые сервисы/команды).

### 🟠 P1 — заметно улучшит продукт

4. **Поставка как `.skill` + `install.sh` + авто-обновление без потери токенов.**
   - Собирать PHP-бинарник (через `composer` baseline) или Phar, ставить в
     `~/.agents/skills/`, токены — в `~/.config/`, не в папке скилла.
   - Довести план из `DEPLOYMENT.md` до работающего one-liner.

5. **Дисциплина в `SKILL.md` по их образцу:**
   - Стартовый выбор режима + русские коды ошибок `APP_TINVEST_...`.
   - **`references/json-fields.md`** с ловушками полей (YTM=null, 0 у коэф.,
     знаки breakdown, порог концентрации, исключение префов из screen shares).
   - Чёткие «сценарии анализа» и «правила подачи данных» (эмодзи по знаку,
     подпись тикеров, дисклеймер ИИР по контексту, запрет читать файл токенов).

6. **ASCII-графики `--chart`** (брайль-линии цены, бары структуры/дохода) —
   детерминированный рендер в самом CLI, поле `chart` в `--json`.

7. **Evals** (`skills/.../evals/evals.json`) — регресс-тесты поведения агента
   по типовым запросам («как мой портфель», «почём сбер», «переключи режим»).
   У нас этого слоя нет совсем — добавит уверенности в качестве промптов.

### 🟡 P2 — полезно, но не срочно

8. **Универсальная карточка инструмента `instrument`** (любой тип в одной команде)
   вместо разброса по типам.
9. **`history --vs IMOEX`** — сравнение цены бумаги с индексом за период (у нас
   есть `moex security:indices` — склеить в единую команду).
10. **`forecast`/`insiders`/`signals`/`favorites`** — обёртки над соответствующими
    методами T-Invest API, если они нам доступны по нашему токену.
11. **`income`** — календарь пассивного дохода (купоны+див на год с итогами по
    месяцам) поверх наших `events:*`.
12. **Локальный кэш** каталога инструментов (сутки) и купонов (неделя) для
    скринеров/allocation — у нас есть кэш в `news-core`, перенести паттерн.

## 4. Что у нас «лишнее» / избыточное (кандидаты на упрощение)

| Элемент | Почему кажется избыточным | Решение |
|---|---|---|
| Шаблоны ассетов дашборда (`Phoenix`, бренды Apple/AMD/Tesla, команды продуктов, изображения команд) | Сотни чужих картинок/иконок «из шаблона» раздувает репозиторий и не относится к финансам. | Вырезать всё лишнее, оставить чистый ECharts-минимализм. Уменьшит вес репо в разы. |
| Дублирующие скиллы: `t-invest-candles` + `moex-candles`; `moex-ticker-analysis` + `t-invest-portfolio-analysis`; `t-invest-trading-calendar` + `moex-trading-calendar` | По два навыка на одну задачу — путает агента. | Слить в единые «канделы» и «календарь» с выбором провайдера внутри. |
| `news-rss` + `news-web` | Перекрытие по смыслу; `news-web` — «поиск по сайтам» слабее RSS. | Объединить под единым `news` с подкомандами, `news-web` оставить как fallback. |
| Куча docs-«планов» (`IMPLEMENTATION-IDEAS`, `MULTI-AGENT-ARCHITECTURE`, `STONKI-ANALYSIS`, `ROADMAP`) | Это наброски/исследования, не актуальная документация — шум для пользователя. | Перенести в `docs/internal/` или `todo/`; из публичных docs оставить только то, что помогает _пользоваться_. |
| Внутренний `memory-core` (отдельный репо) пока пустой/сырой | Лишний репозиторий-обязательство. | Либо довести до минимально полезного, либо свернуть в подсервис `t-invest-agent`. |

> Важно: «лишнее» ≠ «удалить немедленно». Часть из этого — наш **потенциал**
> (рецепты, мониторинг, дашборд, соц. настроения). Упрощать нужно в первую
> очередь **шум и дубли**, а не сильные отличительные фичи.

## 5. Что у нас сильнее (сохранять и развивать)

1. **MOEX ISS как второй источник данных** — конкурент вообще не имеет
   резервного канала. Ценно для надёжности и торгового календаря.
2. **RSS-агрегатор новостей (6 источников)** vs их единственный T-Invest `news`.
3. **Соц. настроения** (SmartLab/MFD/Banki) — уникальный сигнальный слой.
4. **Рецепты + Мониторинг + Память** — «продуктовый» слой агента, которого у них
   нет вовсе. Это наш путь к ценности, недоступной конкуренту.
5. **HTML-дашборд на ECharts** — визуализация, которой у них нет (но требует
   чистки от шаблонного мусора).
6. **Enterprise-архитектура PHP** (DTO/Mappers/Service/ServiceComponent) —
   здоровая база под долгий путь; их «один бандл» труднее сопровождать как
   библиотеку.

«нижних» слоёв (торговля, безопасность, финансовая математика) и упаковки.

охвату, не уступая по глубине и безопасности** — а это уже сильное позиционирование.
